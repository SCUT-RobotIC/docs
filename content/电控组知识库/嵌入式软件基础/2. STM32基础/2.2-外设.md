# 外设

> Ver1.0  
> 本章编者：李融 刘宗远

> MCU的外设（Peripheral），指的是芯片内部、CPU 内核之外的一组硬件功能模块，用来完成输入输出、通信、定时、模拟采样等任务。很显然，一个CPU如果没有硬件定时器、GPIO驱动等等各类外设资源，是无法高效准确地完成控制任务的。当然，外设是一个相对于CPU内核的概念，并不指代芯片外的各类传感器、屏幕、电机等等。学会使用STM32，一个重点是学会使用上面的外设。
> 
> 为了知识体系的完善，这里编入了软件第一章讲义的一部分内容，可能会有你熟悉的部分。
> 另外，和通信有关的外设另起一章。

## GPIO
### 信号电平与驱动能力
- **数字电路怎么判断"1"和"0"？**
- **为什么 3.3V 和 5V 的设备不能随便对接？**
- **一个 IO 最多能驱动多大的负载？**

> [!Warning] 电压等级必须严格匹配
> STM32 靠 3.3V 供电，虽然它的 IO 大多是 5V 容忍的（数据手册里带 FT 标记的引脚），**但最好不要将 5V 设备接入，更不能直接使用 5V 电源供电**；同理它输出的高电平也只有 3.3V，无法直接驱动信号电平为 5V 的设备。3.3V 有时记作 3V3。
>
> 电压等级是嵌入式开发需要非常注重的问题：普通 USB 设备的默认输出为 5V，而一般开发板的允许供电电压为 5V 或 3.3V，通过降压芯片或直接给芯片提供 3.3V 输入，一些调试器也会提供经过降压的 3.3V 接口。无论是输入还是输出，必须严格匹配电压等级（一般会在丝印上标注），否则极易造成设备损坏。

> [!Warning] 驱动能力同样是硬指标
> 接口的输入/输出电压并不是接口的唯一属性，输出的电流强度（功率强度）**同样非常重要，绝对不可忽视**。单片机单个 IO 的驱动能力有限（一般 20mA 量级，整片芯片还有总电流上限）。驱动电机等大电流负载，必须经过三极管 / MOS 管或专门的驱动芯片。
>
> 相对的，普通电脑的 USB 设备默认只能输出 1A 左右的最大电流。只要给设备供电，就必须考虑接口的供电能力和设备所需的额定电流。

### GPIO的基础功能
- **推挽和开漏在电气上的区别是什么？**
- **按键消抖的必要性，实现方法**

| 模式        | 典型用途                       |
| --------- | -------------------------- |
| 输入浮空      | 外部已有上下拉，或者信号本身是推挽驱动        |
| 输入上拉 / 下拉 | 按键、开关，另一头接地或接电源            |
| 模拟输入      | ADC 采样                     |
| 输出推挽      | 驱动 LED、驱动 MOS 栅极，能输出高也能拉低  |
| 输出开漏      | 总线或其它需要线与的场合、电平转换          |
| 复用推挽      | 串口 TX、SPI 的 SCK/MOSI 等外设输出 |
| 复用开漏      | I2C 的 SCL/SDA等，由外设控制时序     |
#### 函数原型和基本实现

```c
// 输出：向引脚写高/低电平
void HAL_GPIO_WritePin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin, GPIO_PinState PinState);

// 输入：读取引脚当前电平
GPIO_PinState HAL_GPIO_ReadPin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin);

// 翻转：当前输出取反（LED 闪烁常用）
HAL_StatusTypeDef HAL_GPIO_TogglePin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin);
```

- `GPIOx`：**端口**，`GPIOA`~`GPIOG` 这类，是指向端口寄存器组的指针。
- `GPIO_Pin`：**引脚号**，`GPIO_PIN_0` ~ `GPIO_PIN_15`。它是**16 位的位掩码**而不是编号，所以可以用按位或一次传多个引脚，如 `GPIO_PIN_0 | GPIO_PIN_1`。
- `PinState`：`GPIO_PIN_SET`（高）或 `GPIO_PIN_RESET`（低）。

`ReadPin` 的返回值就是 `GPIO_PinState` 枚举，典型判断写法：

```c
if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_SET) {
    // 引脚为高电平
}
```

### 外部中断（EXTI）
- **EXTI的内部上下拉和触发边沿的配置方式**
- **PA0 和 PB0 可以同时作为外部中断源吗？**

EXTI 是"外部中断/事件控制器"，负责把引脚上的电平变化变成中断。触发方式有上升沿、下降沿、双边沿，也可以配成电平触发。

外部中断的处理链条：
```
EXTI0_IRQHandler()          // 启动文件里的向量，你在 it.c 里实现
  └─ HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0)   // 清标志，然后调回调
       └─ HAL_GPIO_EXTI_Callback(GPIO_PIN_0) // 弱函数，用户自己重写
```

#### 函数原型和基本实现
老样子，用户只需要重写**回调函数**。一般写法是这样：

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    switch (GPIO_Pin) {
        case GPIO_PIN_0:
            // 第 0 号线的引脚触发了
            break;
        case GPIO_PIN_8:
            // 第 8 号线的引脚触发了
            break;
        default:
            break;
    }
}
```

**别忘了对中断函数编写的统一要求。**

> [!Warning] 外部中断会复用引脚编号
> 你可能发现了外部中断回调函数只传递了引脚号一个参数，但却没说它是哪一个GPIO的。这是因为**EXTI 线是按引脚编号复用的**，EXTI0 只能接某一个端口的第 0 脚，通过一个多路选择器决定到底是 PA0、PB0 还是 PC0。这就意味着**在同一时刻，PA1,PB1,...只能有一个作为外部中断源**。

#### 基本配置流程
- **Pinout**：在视图中左键单击目标引脚并设置为GPIO，比如：`PA8` → `GPIO_EXTI8`

	以`External Interrupt Mode with Falling edge trigger detection`为例，下降沿指的是电平由高变低的边沿触发，使用什么边沿触发显然要看按钮的接法，在此不再赘述。
- **GPIO Pull-up/Pull-down**：
	上拉的作用是让引脚在按键未按下时有确定的高电平，否则悬空有可能产生以外触发。因此引脚提供了内部上下拉来让电平保持稳定。这个上下拉是弱上拉/下拉，因此可以认为他会被外部的强驱动所改变。设置上拉还是下拉需要和触发边沿向匹配，比如如果按钮另一头接GND，那么需要内部上拉+下降沿触发。

### 引脚复用
每个引脚在芯片内部都连着一个多路选择器，选择器的一端是 GPIO 控制器，另一端是各种外设（USART、SPI、TIM……）。配成"复用"模式，即可把选择器拨到外设那边。当然，在使用cube的时候就不用想这么多，只要在Pinout视图里面点就行了。接下来讲的几种用法基本上都涉及了GPIO的复用。

> [!Note] 【扩展】CUBE配了什么
> - **GPIO 模式寄存器**：内核通过配置寄存器来配置外设。对应引脚的 CNF/MODE 位会被配成复用输出，并按外设的电气要求选复用推挽（UART TX、SPI 的 SCK/MOSI）或复用开漏（I2C 的 SCL/SDA）。
> - **两个时钟**：使能引脚所在 GPIO 端口的时钟，同时使能该外设自己的时钟
> - **外设本体初始化**，如果一个引脚上有多种复用，还需要通过AFR指定复用功能
>

## 定时器与 PWM
### 时基单元
- **PSC、CNT、ARR 三者的关系**

定时器的核心是一个计数器 `CNT`，它每个时钟周期加一（或减一），加到 `ARR` 就归零并产生一次更新事件。`PSC` 是预分频器，用于将输入时钟先进行分频降速。

```
TIMxCLK ──[PSC+1]──> CNT 的计数频率 ──[ARR+1 个数]──> 一次更新事件
```

所以定时频率是：
$$
f = \frac{\mathrm{CLK}}{(\mathrm{PSC} + 1) \times (\mathrm{ARR} + 1)}
$$

为什么是 `(PSC + 1)` 和 `(ARR + 1)`，而不是 `PSC` 和 `ARR`？因为这两个寄存器都是从 0 开始数的。

**计数模式**有三种：向上（0 → ARR）、向下（ARR → 0）、中心对齐（0 → ARR → 0）。中心对齐模式产生的 PWM 是对称的，谐波更低，主要用于电机控制。

`PSC` 和 `ARR` 带有缓冲的，写入的新值不会立刻生效，等到下一次更新事件才装载。这个设计是为了避免计数器跑到一半被改值导致周期错乱
#### 函数原型和基本实现

```c
HAL_TIM_Base_Start(&htim1);         // 只让定时器计数，不进中断
HAL_TIM_Base_Start_IT(&htim1);      // 启动并打开更新中断
```

要启动中断，需要现在Cube中正确配置。

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM1)     // 多个定时器时靠 Instance 区分
    {
        // 每 1ms 进来一次
    }
}
```
### PWM
- **占空比和 CCR 是什么关系？分辨率由谁决定？**

PWM 用的是定时器的**输出比较**通道。依然借助定时器`CNT`，使用`CCR` 设置阈值，当`CNT < CCR`时输出一种电平（默认高），`CNT ≥ CCR` 时输出另一种（默认低）。于是占空比为：
`CCR / (ARR + 1)`
频率就是定时器的更新频率。在默认情况下，`CCR = 0` 时占空比为0%，`CCR = ARR` 为100%。当然，PWM波的极性是可以反转的，效果就是高低电平出现的情况直接相反。
#### 函数原型

```c
/* USER CODE BEGIN 2 */
HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_1);              // 开启 PWM 输出
__HAL_TIM_SetCompare(&htim1, TIM_CHANNEL_1, 500);      
									  // 设 CCR：ARR=999 时即 50% 占空比
/* USER CODE END 2 */
```

- **频率和分辨率是互相牵制的**。ARR 越大，占空比能调的档位越多（分辨率高），但同样的时钟下频率就越低。
- 如果只改改占空比，**只动 CCR，不要改 ARR**。动 ARR 会同时改变频率。

> [!Note] 使用PWM进行电机调速
> 
> 你们焊接的小风扇实际上就是在原理上就是使用PWM波调速的。直流电机的转速近似正比于电枢电压，PWM 通过快速通断，让电机“看到“平均电压，电机的机械惯性和电感会把这个方波平滑掉。
>
> 可以思考一下：在这个场景下，PWM的频率不同会对电机控制产生什么影响？应该怎么选取？

## DMA
假设我们需要用IO接收1000个字节存进数组，按我们所学的知识只有两种方法：
- **轮询**：CPU 自己跑循环 `while(没收到); buf[i++] = DR;`，搬 1000 次，期间什么都干不了；
- **逐字节中断**：每来 1 字节进一次中断，可是通讯速度一上来，CPU响应一大堆中断里面和切换上下文本身就会成为性能瓶颈。

搬运数据这么低级的工作，其实没必要让CPU自己去做。所以我们发明了一种可以自己搬运数据的外设：DMA。

DMA（Direct Memory Access,直接存储区访问）为实现数据高速在外设寄存器与存储器之间或者存储器与存储器之间传输提供了高效的方法，数据移动过程**无需任何CPU操作控制**。从硬件层次上来说，DMA控制器是独立于内核的外设，类似定时器、GPIO等，只不过DMA的功能是可以快速搬运数据。

CPU 使用 DMA 时，只需要发送搬运指令：

```
源地址（外设 DR / 内存）→ 目的地址（内存 / 外设 DR）→ 长度
```

之后 DMA 自己循环：外设每产生一次请求（如 USART 收到一个字节），它就搬一个数据、地址自动加一个增量、计数减一；减到零发一次**传输完成中断**叫 CPU 收尾。在这个过程中，DMA会自己搬运数据。

判断传输结束一般有三种方式：轮询完成标志位、开启传输完成中断在回调里处理、以及后面通信一章会讲的 **DMA + 空闲中断**组合（处理不定长数据的标准做法）。

DMA本身不自己发起传输，一般是通过其它外设的DMA请求线来发起请求。所以在配置时，外设的DMA使能和本身的DMA通道都需要启用，在串口一节会详细说明。

在F103中，DMA1的7个通道各自对应固定的几个外设请求，而更高级的内核则可以进行数据路由，把通道和外设彻底解耦，任意请求可映射到任意通道。

> [!Info] DMA主要在涉及通讯的地方最为常用，我们会以UART作为例子，在下一章中具体讲解。

## ADC
### 采样
- 解释数字信号和模拟信号的区别放到
- 解释ADC的含义
- 理解什么是采样

STM32 的 ADC 是**逐次逼近型（SAR）**：内部有个 DAC 不断猜测，逐位比较，猜 12 次就得到 12 位结果。所以一次转换的时间由两部分组成：**采样时间**（采样保持电路给内部电容充电）+ **逐次比较时间**（固定 12 个周期左右）。

采样时间设得太短，电容没充满，读数就会偏低——这是"测电压总是不准"的常见原因。被测信号源内阻越大，需要的采样时间越长。

12 位分辨率意味着满量程被分成 4096 份。如果参考电压是 3.3V，那么精度大概是：

```
1 LSB = 3.3V / 4096 ≈ 0.806 mV
```

ADC有三种模式：
- **单次**：触发一次转一次。要读多路就轮流切换通道。
- **连续**：转完立刻转下一次。适合实时监测。
- **扫描**：按顺序把一组通道全部转一遍。多路采样时用，通常配合 DMA 把结果搬到数组里。
