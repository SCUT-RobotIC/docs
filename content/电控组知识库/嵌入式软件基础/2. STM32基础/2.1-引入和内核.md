## 认识 STM32
### 单片机是什么
- **STM32中的32是什么含义？32位意味着什么？**
- **一颗单片机上都有哪些部分，各自干什么？**

 我们常常把STM32这类芯片叫MCU（Microcontroller Unit）或是单片机，是一种集成了一整套微型计算机系统（CPU、内存、存储器、各种输入/输出接口）在一块芯片上的集成电路。这类芯片在更高性能的领域有一个近义词，那就是SoC（System on Chip）。MCU占用体积小，功耗低，实时性强，所以在机器人、物联网、智能穿戴设备等领域使用广泛。
 
STM32型号的每一位有都具体含义。以现在你们应该已经比较熟悉的 `STM32F103C8T6` 为例：
- `STM32`：ST公司的MCU产品线，特点是使用32 位 ARM 内核。
- `F`：子系列定位，H 是高性能，F 是通用型，L 是低功耗，G 是主流型。
- `103`：具体型号，数字越大外设越丰富。
- `C`：引脚数，C 表示 48 脚。
- `8`：Flash 容量，8 表示 64KB。
- `T`：封装，T 是 LQFP。
- `6`：温度等级，6 是 -40 ~ 85 ℃。

## 开发STM32
### HAL 库
- **简单了解标准库、HAL 库、LL 库**
- **简单了解使用HAL库工程的文件结构**

>[!Note] HAL库
>早期写 STM32 有两种方式：直接对着参考手册写寄存器，或者用 ST 的标准外设库（StdPeriph）。写寄存器快但可读性和可移植性差，标准库目前也已经停止维护，取而代之的是HAL库和LL库。HAL意为**Hardware Abstraction Layer，硬件抽象层**，它提供了大量统一且与芯片型号无关的外设控制方法，可以屏蔽硬件差异、提供统一 API，并提升系统的可移植性与稳定性。**用HAL库开发是 ST 现在主推的开发框架，也是我们的学习目标**。其提供的接口有一些共性特点：
>- 每个外设对应一组 `stm32xxx_hal_xxx.c/.h`。
>- 用**句柄结构体**（`UART_HandleTypeDef` 这类）保存外设的全部状态和配置。
>- 提供轮询、中断、DMA 三种接口，命名上分别是 `HAL_xxx()`、`HAL_xxx_IT()`、`HAL_xxx_DMA()`。
>- 事件通过**弱函数回调**通知上层，你在自己的文件里重新定义一次就能接管。
>HAL 库提供的函数一般如下命名：
>```
>HAL_外设名_函数功能(参数1, 参数2, ...);
>```
>其中函数功能采用驼峰式命名。
>
>HAL库当中重要的几个文件：
>- `stm32xxx_hal_conf.h`：裁剪开关，决定哪些外设模块参与编译。
>- `stm32xxx_hal_msp.c`：**MSP** 是 MCU Support Package，用于详细配置外设，包括时钟使能、GPIO 复用、NVIC 配置等。CubeMX 生成的 `HAL_xxx_MspInit()` 就在这里。
>- `stm32xxx_it.c`：中断服务函数
>- `system_stm32xxx.c`：包含`SystemInit()` 的实现，负责最基本的时钟和向量表设置等

> [!Note] 通过句柄传递参数
> 一个芯片可能有 6 个串口，函数不可能为每个串口写一份。句柄就是区分具体实例的方法。`HAL_UART_Transmit(&huart1, ...)` 里的 `&huart1` 既告诉库用哪个外设实例，也带回这次传输的状态和错误码。这是一个可以借鉴的封装策略。

### CubeMX 与 MDK 工程
- **`.ioc` 文件和生成的代码是什么关系？**
- **重新生成会不会覆盖用户代码？用户代码应该写在哪？**
- **掌握debug选项的配置方法**

CubeMX 的核心是一个 `.ioc` 配置文件。它提供图形界面里用于配置引脚、时钟、外设等，然后按模板生成代码。

> [!Warning] 在正确的位置编写用户代码
> 生成器会在每段可编辑区域周围插入成对的注释：
> ```c
> /* USER CODE BEGIN 2 */
> // 你的代码写在这里，重新生成时会被保留
> /* USER CODE END 2 */
> ```
> **写在 `USER CODE BEGIN/END` 之外的内容默认会在下次生成时被删除。**
### 烧录与调试
- **烧录和调试是一回事吗？**
- **掌握keil软件断点、单步、Watch 窗口的基本使用方法**

STM32 常用的调试接口是 **SWD**（Serial Wire Debug），一般包含：
- `SWDIO`：双向数据线
- `SWCLK`：时钟线
- 外加 `GND`，通常再接 `3V3` 给调试器参考电平。

SWD 是 ARM 定义的debug协议，DAP-Link 和 ST-Link 是他最流行的两种实现，他们的区别主要是厂商和配套软件，另外DAP是开源协议。如果你购买的是pwlink，它也是DAP-link的一种。

除了SWD协议，还有一种调试协议是JTAG。JTAG是一种通用的硬件debug协议，你可以在除ARM以外的其它架构MCU，甚至FPGA上见到它们的影子。不过JTAG引脚数量较多，占用PCB体积比较大，所以在STM开发板上不一定具备。

更多参考：
[keil的debug功能_keil debug](https://blog.csdn.net/2301_77540313/article/details/142523143)

> [!Warning] 任何工程都必须设置 Debug 选项
>  任何工程都必须设置Debug选项，不设置此项将造成芯片无法调试和烧录。如果使用SWD调试，选择Serial wire。

> [!Note] 【扩展】异常和错误
> Cortex-M 把所有"能打断正常执行"的事件统称为**异常**（exception），分成两类：
> - **外设中断**：编号从 0 开始，每个外设中断在这里占一个号。
> - **系统异常**：编号为负：`-14` NMI、`-13` HardFault、`-12` MemManage、`-11` BusFault、`-10` UsageFault、`-5` SVCall、`-4` DebugMon、`-2` PendSV、`-1` SysTick。这些由内核直接管理。要注意的是，异常不等于错误，系统异常也不等于错误，这其中只有HardFault、BusFault和UsageFault三种属于ARM定义的错误类型。
> 
> 三种错误表示了什么情况，ARM的手册里面有[详细介绍](https://support.arm.com/documentation/dui0552/a/the-cortex-m3-processor/fault-handling/fault-types?lang=en)，可以自行阅读。这里主要提一下错误的[升级（escalate）机制](https://support.arm.com/documentation/dui0552/a/the-cortex-m3-processor/fault-handling/fault-escalation-and-hard-faults)。文档里面提到一种升级条件：`A fault occurs and the handler for that fault is not enabled.` 和中断一样，错误也是有一个实现错误处理函数的入口的，而在STM32的工程中，对UsageFault和BusFault默认都不启用，**这就意味着其实我们一般只能看到HardFault一种错误**。而至于你实际上可能犯的错误可就五花八门了。
> 
> 在默认情况下，如果hardfault被触发，你看到的情况大概只是程序卡死，不再响应的你的任何操作。进入debug点停止运行，你会发现程序跑进了`HardFault_Handler()`，这个时候就可以确诊了。
> 
> 有关利用Keil检查hardfault的方法可以参考[这篇文章](https://blog.csdn.net/m0_74676415/article/details/144341038)，不过我要劝一句，如果真的出现了HardFault，我建议你首先检查一下代码有没有危险的地址访问，或者除0之类的操作问题，因为利用HardFault倒查的过程非常痛苦。当然如果有兴趣可以研究一下CmBacktrace等辅助工具。
> 
> 更多参考：
> [Cortex-M3 Devices Generic User Guide](https://support.arm.com/documentation/dui0552/a?lang=en)
> [How to debug a HardFault on an ARM Cortex-M MCU | Interrupt](https://interrupt.memfault.com/blog/cortex-m-hardfault-debug)

## 中断

### 中断的概念
- **什么是中断？和轮询相比，它付出了什么代价？**
- **中断服务函数是在哪里被调用的？**
- **【扩展】什么是弱函数？**

中断就是把 CPU 从当前任务中临时打断，运行我们需要的任务，处理完再回来。它的优点是节省 CPU 资源、快速响应、可以进行任务优先级管理。

STM32 + HAL 的中断处理流程一般是：
```
中断发生 → NVIC（中断控制器：判优先级、使能/屏蔽）
        → 中断服务函数 XXX_IRQHandler（向量表入口，在 stm32xxxx_it.c，CubeMX 生成）
        → HAL 公共入口（如 HAL_GPIO_IRQHandler / HAL_TIM_IRQHandler，负责清标志）
        → 中断回调函数 XXXCallback（在 main.c，用户写） 
```

对于这一整条链路，我们只需要写最后一行的回调函数就可以了。不同中断的回调函数名字各不相同，由于系统已经注册了这个名字，所以**不能打错**。

> [!Warning] 不要写错中断函数的名字
> 启动文件为每个中断都准备了一个**弱定义**的空处理函数。如果你实现 `HAL_xxx_Callback` 时拼错了名字，链接器不会报错，但是他永远不会被调用。

内核在进入中断前会自动保存现场，退出时自动恢复。写中断服务函数要遵守以下要求：
- **越短越好**
- **不要放阻塞函数**（如 `HAL_Delay`）
- 尽量避免中断嵌套
核心思想其实就是一点：中断必须短平快，才能发挥它灵活省事的优点。

> [!Note] 【扩展】向量表和NVIC
> 向量表是一张存储在Flash起始地址的表格，里面按顺序存放着每个异常/中断对应的处理函数入口地址。每个中断都有一个固定的编号，向量表里就在对应位置写上这个中断的处理函数地址。
> 
> NVIC，全称Nested Vectored Interrupt Controller，即嵌套向量中断控制器，是ARM Cortex-M内核中专门用于管理中断的核心外设。它的主要职责包括使能或禁用中断源、设置中断优先级、处理中断嵌套以及响应中断请求并自动跳转到对应的中断服务函数入口地址。从硬件上来说，NVIC帮助CPU查询向量表计算中断服务函数地址，并处理优先级，从而保证CPU有序、高效地处理每一个中断任务。
### 中断优先级
- **抢占优先级和子优先级的区别**

每个中断的优先级寄存器有 8 位，但 STM32 只使用高 4 位，**数字越小优先级越高**。
这 4 位又被分成两段：**抢占优先级**和**子优先级**。两者的区别是：
- 抢占优先级决定**能不能打断**。高抢占优先级的中断可以打断正在执行的低抢占优先级中断。
- 子优先级只决定**同时挂起时谁先执行**。它不能打断正在执行的中断。

4位数字如何被切分成抢占优先级和子优先级，这就是优先级的分组问题：

| 分组      | 抢占位 | 子优先级位 | 抢占级数      |
| ------- | --- | ----- | --------- |
| Group 0 | 0   | 4     | 1（等于没有抢占） |
| Group 1 | 1   | 3     | 2         |
| Group 2 | 2   | 2     | 4         |
| Group 3 | 3   | 1     | 8         |
| Group 4 | 4   | 0     | 16        |

HAL 默认用 **Group 4**，也就是 16 级抢占、没有子优先级。

> [!Note] 【扩展】中断标志位
> 每个中断源内部都有一个**标志位**（注意一个外设可能不止有一个中断源）：事件发生时（按键按下、串口收到一个字节、定时器数溢出），硬件自动把状态寄存器里的对应标志位置 1，并向 NVIC 发出请求。比如 USART 的 RXNE（收到数据）、TIM 的 UIF（更新溢出）等等。NVIC自己其实并不区分外设具体是什么，它只需要通过标志位管理好自己的中断通道就可以了。
> 
> 处理完中断后，必须要清除中断标志位（清除它的值），否则下一个同类中断就无法再次触发。清除标志位在使用HAL库时在IRQ_Handler中已被实现。

## 时钟
- **时钟源有哪几个？HSI、HSE、LSI、LSE 用途是什么？**
- **【扩展】简单了解数字电路，理解什么是时序逻辑，时钟在其中的作用是什么**
- **【扩展】简单了解PLL和分频/倍频的原理**
### 时钟源
时钟是时序逻辑的灵魂。更直接的说法是，时钟是整颗芯片的节拍。没有时钟，CPU 不执行，外设无法正常工作。STM32 有四个时钟源：
- **HSI**：内部高速 RC，约 16MHz，精度差但不需要外部器件，可以作为"救急"时钟。
- **HSE**：外部晶振，一般是 8MHz。精度高，是正常工作的首选。
- **LSI**：内部低速，约 32kHz，主要给看门狗和 RTC 用。
- **LSE**：外部低速晶振，32.768kHz，给 RTC 用。

我们暂时不需要关注两个低速时钟。至于高速时钟，由于外部晶振精度比较高，而且开发板往往带有外部晶振（你可以在板子上找到一个胶囊形状的金属屏蔽罩，这下面就是晶振），所以我们往往配置使用外部高速时钟就可以了。
### 时钟树
不同模块所需要的时钟频率不一定是一样的。时钟源通过倍频或分频配置出不同的时钟频率供核心和各类外设使用，这就形成了时钟树。

## 【扩展】Cortex-M内核
### ARM、Cortex 与 STM32
我们平时说的ARM有三层含义：
- **ARM 公司**：一家英国芯片设计公司，arm**自己不生产芯片**，只设计 CPU 内核并授权给别人使用。
- **ARM 架构**：ARM 公司定义的指令集规范，比如 ARMv7-M、ARMv8-M，规定了 CPU 能接受哪些指令、有哪些寄存器等。
- **ARM 内核**：ARM 公司按架构设计出的具体CPU实现，Cortex 系列就是其中最成功的产品线。除了ARM自己，也有许多公司购买ARM架构授权并自行设计芯片。

Cortex 家族按用途分成三个系列：
- **Cortex-A**：跑 Linux 的高性能应用处理器，用于手机、树莓派等。
- **Cortex-R**：面向实时性要求极高的场合，比如硬盘控制器、汽车安全系统。
- **Cortex-M**：面向微控制器的低功耗内核，也就是 STM32 使用的系列。常见型号有 M0/M0+、M3、M4、M7 等，数字越大性能越强、外设和指令集越丰富。我们常用的 F103 是 Cortex-M3。

ARM 公司设计 Cortex-M 内核 → ST 公司购买授权，在内核外围加上 Flash、SRAM、外设 → 封装成一颗 STM32 芯片。不同厂商（ST、NXP、GD……）的 Cortex-M MCU在内核层面几乎一样，区别只在外设。
### 内核做什么
CPU 的工作简单来说是一个无限循环：**取指 → 译码 → 执行**。它从 PC（程序计数器）指向的内存地址取出一条指令，解析指令的含义，执行，然后 PC 指向下一条，周而复始。现代内核会用**流水线**让几条指令的不同阶段重叠起来提高速度，这里不展开。

Cortex-M 内核对外可见的寄存器一共十几个，编程时最需要知道的是这几个：

| 寄存器 | 作用 |
| --- | --- |
| R0–R12 | 通用寄存器，运算的中间结果都放这里 |
| R13（SP） | 栈指针，指向当前栈顶 |
| R14（LR） | 链接寄存器，函数调用时保存返回地址 |
| R15（PC） | 程序计数器，指向正在执行的指令 |
| xPSR | 程序状态寄存器，存放运算标志（是否为0、是否进位等） |

寄存器位于 CPU 内部，访问速度远快于内存，但数量极少。C 语言里的局部变量，如果编译器安排得下，就会放在寄存器里以待取用。

> [!Note] Thumb 指令集
> 早期的 ARM 内核每条指令固定 32 位。Cortex-M 全系只支持 **Thumb/Thumb-2** 指令集，指令可以是 16 位或 32 位混排，同样的程序占用更少的 Flash
### 内核的运行模式
Cortex-M 内核有两种运行模式：
- **线程模式（Thread mode）**：正常运行主程序时的模式。
- **处理模式（Handler mode）**：执行中断/异常服务函数时的模式。

再叠加**特权级**（特权/非特权），就构成了内核的权限体系。这套机制主要用于操作系统，裸机开发时程序始终运行在特权级，在此不作过多介绍。

## 【扩展】内存与启动
### 内存布局
- **理解寄存器、RAM和ROM的区别，STM32片上SRAM和Flash的区别**
- **什么是内存地址？在STM32中1word是多大？**
- **什么是大端/小端字节序？**
- **32位CPU最多可以管理多大的地址空间？**

Cortex-M 是32位内核，也就具有32位地址空间。同时ARM将所有空间分为以下几块：

| 地址范围                          | 用途                      |
| ----------------------------- | ----------------------- |
| `0x0000_0000` – `0x1FFF_FFFF` | Code 区，用于存放程序           |
| `0x2000_0000` – `0x3FFF_FFFF` | SRAM                    |
| `0x4000_0000` – `0x5FFF_FFFF` | 外设寄存器                   |
| `0x6000_0000` – `0x9FFF_FFFF` | 外部存储器（FMC / QSPI）       |
| `0xE000_0000` – `0xE00F_FFFF` | 内核私有外设：NVIC、SysTick、SCB |
更加细化地表示：

![Pasted image 20261109144101.png](<assets/Pasted image 20261109144101.png>)
*ARM Cotrex-M3权威指南*，P84

注意，地址空间决定了内核最多可以通过地址管理的空间上限，但是MCU不一定真的装了这么多内存。你可能听说过32位电脑最大只能支持4GB内存，也是一样的道理。

>[!Note] 位带区
>
> 平时 CPU 能直接操作的最小单位是字节，对寄存器则是一次 32 位的字操作。但 Cortex-M3 提供了一个特殊机制：在两个特定地址区间内，可以独立访问每一个比特位，这两个区间就叫位带区（bit-band region）。原理其实就是别名：位带区里的每一个比特，都在对应的**位带别名区**中映射为一个专属的 32 位字，往别名地址写 1 等效于把原位置 1，写 0 等效于把原 bit 清 0。
> 
> 这样做的最大价值主要是便利的位操作和对位操作的原子性保证，不过实现这个需求方法其实有很多，比较现代的ARM内核也不一定会支持位带操作，在这里仅作了解。
>

### 程序的内存结构
定义一个变量，对于单片机来说，背后可能发生了一连串的事情：
1. 编译时：编译器在可执行文件中划出一块区域，写上数值 `100`
2. 烧录时：这个 `100` 被写进了 Flash 的某个地址
3. 启动时：复位后，启动代码把这个 `100` 从 Flash 拷贝到 RAM 中对应的位置
4. 运行时：CPU 每次访问 `count`，实际上都是在操作 RAM 里的那个地址

不同的变量，读写需求和生命周期完全不同。有的只读，有的需要可写；有的程序启动就存在直到关机，有的函数调用时才诞生、结束就消失。为了管理这些差异，编译器把内存划分成了几个不同的区域，每个区域有不同的用途和特性。

一般而言，程序被加载到裸机/操作系统后，所占用的全部内存空间可以被大概分下面几种：
- 代码段（.param）：顾名思义指存放的是编译好的机器指令，只读。
- 数据段（.data）：存放所有已经经过初始化的数据。广义的数据段包括了（或者也可以认为它们是单独的段）：
	- 只读常量（.rodata）：包含全局常量、字面值常量、枚举类型等等）
	- 已初始化的（非0）全局变量和静态变量（.data，其实可能还包含了一些局部常量）：
	- 未初始化（或初始化为0）的全局变量和静态变量（.bss，之所以要区分.bss和.data是因为bss段不需要存初值，几乎不占用数据段）
- 堆（Heap）：用来存放运行时通过new申请的内存，动态分配，手动管理，可以以任意顺序申请释放
- 栈（Stack）：剩下的函数参数、局部变量所占用的空间，动态分配，自动管理，遵守LIFO

视平台不同，在运行时这些内容的部分或全部会被加载到RAM中，一般至少会包含data），bss（并且bss会在RAM中完全展开），堆和栈。

可以发现，变量的值只可能存在于三个地方：全局/静态区（data和bss），堆或者栈。

> [!Tip] `.data` 既占 Flash 又占 RAM
> 在`.data`中存储的数据具有初值，所以需要掉电不丢失，而在运行时又必须能被修改，所以既占用Falsh 的空间也占用SRAM的空间。启动时 `__main` 会把初值从 Flash 拷贝到 SRAM，而`.bss` 则只在 RAM 里展开，不占 Flash 空间。所以，把大数组初始化为0会比初始化为1省下一些Flash空间。

> [!Note] 栈和栈指针
> 之前提到过SP，栈指针，你也可能已经在许多地方看到过栈这个名字。栈本身是一种数据结构，它的特点是后进先出（LIFO）。
>![Pasted image 20261110005038.png|300](<assets/Pasted image 20261110005038.png>)
> 在CPU系统中，往往使用栈这种数据结构来管理**函数调用**。每调用一个函数，就往栈里"压"一项内容，叫**栈帧**，里面放着这个函数的局部变量、参数，以及返回地址和调用前需要保存的寄存器，函数返回时再逐层按相反顺序"弹"出来，这样的设计使得函数的嵌套、递归得以高效和正确的工作。
> 
> 这块内存就在MCU的SRAM 里，而SP（R13）寄存器始终指向当前栈的顶端，让我们能够了解栈的使用情况。Cortex-M 的栈是**向下生长**的：压栈时 SP 减小，弹栈时 SP 增大。这样，堆向上生长，栈向下生长，甲乙两个施工队同时往中间修路，可以更加高效地使用内存空间。复位后第一个字被放进 SP，所以向量表的第一项就是这个栈的初始栈顶，栈的大小也就在这时确定了下来。
> 
> ![Pasted image 20261109145647.png|300](<assets/Pasted image 20261109145647.png>)
> 
> 栈的空间是有限的。局部数组开太大、递归太深，栈就会越过边界踩到别的数据，这就是**栈溢出**。

### 启动
- **STM32的启动模式有几种？**
- **什么是启动文件？**
#### 启动模式与重映射
在Cortex-M3核心中，CPU 必须从 `0x0000_0000` 启动。上电或复位之后，CPU 做的事是固定的：从 `0x0000_0000` 读出第一个字，放进栈指针 SP；从 `0x0000_0004` 读出第二个字，放进程序计数器 PC。因此，第二个字指向的地址就是整个程序第一条指令的入口。一般情况下，这个地址指向**复位服务函数 `Reset_Handler`**，主要负责初始化时钟等底层硬件、准备 .data/.bss 段，最后调用 `main()` 进入你的程序。

不过，实际上 STM32 的 Flash 物理地址在 `0x0800_0000`。ST 的解决办法是**重映射（remap）**：复位瞬间，硬件根据 BOOT 引脚的电平，自动把选中的存储区"映射"到 `0x0000_0000`。之所以不把Flash直接放在`0x0000_0000`，是为了更好地兼容不同地启动模式。STM32 共有三种启动模式：

![Pasted image 20261109150741.png](<assets/Pasted image 20261109150741.png>)
*reference manual*, P60

BOOT0/BOOT1 两个引脚的电平组合决定选哪种模式。开发板上 BOOT0 一般通过跳线帽接地，所以默认使用主Flash启动。他们启动的地址是：

| 启动模式        | 映射到 0x0 的区域                   | 用途                               |
| ----------- | ----------------------------- | -------------------------------- |
| 主 Flash 存储器 | `0x0800_0000`                 | 正常模式，你烧录的程序就在这里运行                |
| 系统存储器       | 芯片内置的 Bootloader（放在Block0的最后） | STM部署的bootloader程序，可以通过串口给芯片下载程序 |
| SRAM        | `0x2000_0000`                 | 程序在 RAM 里运行，调试或特殊用途，掉电即失         |
从Flash启动时，一次上电到 `main()` 的完整流程大致是：

```
复位 → 硬件按向量表装载 SP 和 PC → Reset_Handler
     → SystemInit()（配置时钟、设置向量表偏移）
     → __main（把 .data 初值从 Flash 拷到 SRAM、.bss 清零、准备堆栈）
     → main()
```
#### 启动文件
启动文件是 ST 提供的一段汇编代码（一般命名为 `startup_xxx.s`，在Keil 工程里能看到它），主要的功能是：
1. **提供向量表**：从 `0x0` 地址开始，对应CPU的初始化行为，第一项是初始栈顶地址，一般指向SRAM的底部，第二项是复位服务函数 `Reset_Handler` 的地址，之后按编号依次排列每个中断的处理函数入口。
2. **实现Reset_Handler**
	- 调用 `SystemInit()` 初始化时钟、Flash 等待周期等底层硬件
	- 将 `.data` 段从 Flash（`_sidata`）复制到 SRAM（`_sdata`~`_edata`）
	- 将 `.bss` 段（`_sbss`~`_ebss`）清零
	- 调用 `__libc_init_array()` 执行C库初始化或C++ 全局对象的构造函数
	- 最后调用 `main()` 进入用户程序

这些内容会由连接器连接到你的用户代码上，形成完整的可执行二进制文件。

## 【扩展】外设总线
你可能好奇时钟树里面显示的 AHB 和 APB 是什么东西，它们就是 STM32 的**片上总线**（bus）。内核想读写外设寄存器，需要有一条通道将地址和数据送过去，这就是总线。在内存布局一节已经提到，外设寄存器住在 `0x4000_0000` 开始的地址空间里，CPU控制和访问外设的方式，实际上就是通过总线读写位于这个内存区域的寄存器。
### AHB 与 APB
AHB（Advanced High-performance Bus）和 APB（Advanced Peripheral Bus）都是 ARM 定义的片上总线规范，从名字就能看出分工：**AHB 是高速主干，APB 是低速的外设分支**。以 F103 为例：

![Pasted image 20261109215636.png|700](<assets/Pasted image 20261109215636.png>)
*User Maunal*, P47

| 总线   | 最高频率（F103） | 连接的模块                                           |
| ---- | ---------- | ----------------------------------------------- |
| AHB  | 72 MHz     | 内核、DMA、SRAM、Flash、RCC                           |
| APB2 | 72 MHz     | GPIO、AFIO、ADC、USART1、TIM1/TIM8、SPI1             |
| APB1 | 36 MHz     | 其余 USART/UART、TIM2~7、SPI2/3、I2C、DAC、CAN         |

APB2 和 APB1 通过桥接器挂在 AHB 上，形成主干—支路的树状结构。在F103上，APB的默认频率一般是36MHz，不过你会发现挂在上面的定时器则都和主频一致时72M。

> [!Note] 寄存器地址和总线的对应
> `0x4000_0000` 开始的外设地址空间，实际是按总线分段划分的：APB1 外设在 `0x4000_0000` ~ `0x4000_7FFF`，APB2 外设在 `0x4001_0000` 以上。可以在 Reference Manual 的 memory map 章节查到每个外设的基地址。
