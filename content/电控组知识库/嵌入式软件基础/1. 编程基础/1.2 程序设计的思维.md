## 状态机编程

核心思想：把程序的行为归结为**有限的几个状态**，以及**状态之间跳转的条件**。任意时刻系统只处于其中一个状态，事件（按键按下、串口来数据、定时器到点）触发跳转。

类比自动售货机：投币前是"待机"，投够了是"已付款"，出货后回到"待机"。机器不需要记住全部历史，只需要记住"现在处于哪个状态"。

对比一下朴素写法：裸机程序常见的组织方式是在 main 里堆 if/else 和一堆标志位（flag_key、flag_uart、flag_100ms……）。逻辑一复杂，标志位的组合数呈指数增长，漏掉一个组合就是一个 bug。状态机把"所有历史"压缩成"一个状态变量"，n 个状态就只有 n 种处境。

以"按键短按/长按"为例：

```c
typedef enum { KEY_IDLE, KEY_PRESSED, KEY_LONG } KeyState;
KeyState state = KEY_IDLE;
uint16_t t = 0;

void Key_Scan(void)   // 每 10ms 调用一次
{
    switch (state) {
    case KEY_IDLE:
        if (Key_IsDown()) { state = KEY_PRESSED; t = 0; }
        break;
    case KEY_PRESSED:
        if (!Key_IsDown())   { LED_Toggle();    state = KEY_IDLE; }  // 松手 → 短按
        else if (++t >= 100) { LED_BlinkFast(); state = KEY_LONG;  }  // 1s → 长按
        break;
    case KEY_LONG:
        if (!Key_IsDown()) state = KEY_IDLE;
        break;
    }
}
```

状态机 + 主循环轮询是裸机程序的经典骨架：main 循环轮询各个事件源，事件交给状态机消化。适用于行为可枚举的系统——按键交互、菜单、通信协议解析、流程控制。代价是状态和跳转一多会"状态爆炸"，需要分层状态机等更复杂的组织方式。

## 封装和解耦

封装：把数据和操作它的函数绑在一个模块里，对外只留接口，内部实现藏起来。解耦：模块之间只通过接口说话，谁也不许伸手进别人的内部。

类比插座：墙里线路怎么布、电从哪来你不用知道，你只依赖"220V、两脚/三脚"这个接口。供电方式怎么换，电器照常工作。

C 语言落地手段就三条：

- 一个模块一对 .c/.h：.h 只放"对外的承诺"（函数声明、类型定义），.c 放实现；
- `static` 修饰内部函数和变量，把它们挡在文件作用域内；
- 结构体把一个对象的状态聚在一起，操作函数只接收指向它的指针。

```c
// led.h —— 对外的承诺
void LED_On(uint8_t id);
void LED_Off(uint8_t id);

// led.c —— 实现细节，外界不关心
static GPIO_TypeDef *port = GPIOB;   // static：仅本文件可见
```

封装的直接收益就是解耦：main 只调用 LED_On()，将来换板子、换引脚，只改 led.c 一处。没有封装时，GPIOB 和引脚号散落在全工程，改一次板子就要全局搜一遍。

分寸：接口一旦定下，改接口的成本远高于改实现；为三行代码造一层接口也是负担。判断标准是"这段实现将来会不会被替换、会不会被多处使用"。

## 面向对象编程（OOP）
OOP不只是一种机制，更关键的是它是一种思维。

封装是把"数据 + 操作"打包，OOP 在此之上再加两件事：**继承**（在已有类型上扩展出新类型）和**多态**（同一个接口，不同对象有不同行为）。

C 没有 class 关键字，但 HAL 库处处是 OOP 思维：

- `UART_HandleTypeDef` 这个结构体就是一个"串口对象"：寄存器指针、缓冲区、状态、回调全部打包在内；
- `HAL_UART_Transmit(&huart1, ...)` 的第一个参数就是"这个对象自己"，对应 C++ 里的 this 指针；
- 回调机制（如 `HAL_UART_RxCpltCallback`）是多态的雏形——同一套 HAL 代码，具体行为由你挂上去的函数决定。

多态在 C 里的落地手段是**函数指针**：结构体里放函数指针，不同"对象"填不同函数，调用方只管 `obj->fn(obj)`，这就是"接口不变、行为可换"的实现形式。
## 同步和异步

- **同步**：发起操作后停在这里等结果。串口阻塞发送 `HAL_UART_Transmit()`：CPU 逐字节等标志位，发完才返回。
- **异步**：发起后立即返回去做别的事，结果由中断/回调送达。`HAL_UART_Transmit_IT()`：启动后 CPU 走人，字节由中断填入，全部发完时回调通知你。

类比点外卖：同步是站在窗口盯着师傅炒完；异步是扫码下单该干嘛干嘛，手机响了再去取。

同步的代价是 CPU 空等：发 8 字节只要几十 µs 还能忍，发 1 KB 就是 1 ms，整个控制环停摆。异步的代价是代码被"切碎"：发起、进行中、完成三个阶段分散在不同函数里，中间状态要自己保存——而"保存状态"恰好是上一节状态机的本职。同步易写易调试，异步高效但考验设计，这是嵌入式编程最核心的一对取舍。

在同步与异步之间，还有一位重要的中间角色——**缓冲区**。收发双方速度不匹配时，划一段内存当"蓄水池"：发送方把数据扔进缓冲区就返回（比阻塞发完快得多），字节搬运交给中断或 DMA 在后台慢慢消化；接收方向反过来，中断把到来的字节丢进缓冲区，主循环得空再来取。"何时产生数据"与"何时处理数据"就此解开，双方各自按自己的节奏工作。

缓冲区最常用的结构是环形缓冲区（ring buffer）：读、写两个指针在数组里循环推进，天然免去搬移剩余数据的开销。它也有代价：占内存、引入排队延迟，而且"写指针在中断里推进、读指针在主循环里推进"正是上一节数据竞争最典型的战场。后面串口章节的收发实现会反复用到它。
